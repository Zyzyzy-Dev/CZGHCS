## 目标与边界

从“复制正文最终请求”升级为“独立选择规划资料”：规划 API 使用插件选定的预设和世界书，以及勾选的扩展注入信息。正文 API 继续使用酒馆原配置，只额外接收本轮规划。不得通过短暂切换原生预设、世界书、当前 API 或活动密钥来实现独立选择。

保留 iframe、自有 CSS、五项主题白名单、src 模块化与文件头说明、tests 独立目录。保留自动跟随规划预设标签、失败停止、取消、重生成及方案密钥引用行为。

用户提供的三张设计图是视觉依据，文字修正优先。采用细边框、淡蓝强调、紧凑卡片和清晰分组；使用可点击/键盘操作的真实图标按钮，附 title 与 aria-label。小屏单列，面板内容滚动。右上角设置进入 p1，返回回到先前主标签；预设/世界书分别对应 p2/p3。图中太阳按钮拟作为明暗外观切换，默认跟随酒馆五项主题；本地明暗配色不写回酒馆。

## 设置页

### API 方案

来源分三类：酒馆当前连接、预设更新编辑器方案、创作规划自己的方案。

- 酒馆当前连接在本次调用开始时读取，不切换或保存主连接。
- 预设更新编辑器方案只读，选择后可作为本地方案的来源。
- 新建/覆盖/删除只作用于创作规划自有方案；外部方案和当前连接不提供原地覆盖/删除，明确显示其来源。
- URL、密钥显示/隐藏、模型列表拉取、可手填模型、最大输出和超时控件保留。
- 新建独立方案使用自己的名称和 ID。原生支持的密钥引用优先；输入的新密钥保存至酒馆密钥存储并独立引用，不写入普通插件设置、方案导出、日志或 iframe 状态回包，不改变主 API 活动密钥。
- 删除本地方案仅删除方案记录，不默认删除可能被其他方案引用的密钥。保存/覆盖确认成功后才更新选择项。
- 方案级 URL/认证/附加参数能力以酒馆 1.18.0 已核对路径为准；不支持的连接明确提示，不静默改用其他 API。

### 插件兼容

保留“记忆插件”和“剧情规划插件”两组，逐项复选框，不用下拉选择。

- 首批：记忆/柏宝书，剧情规划/构画。显示已检测、未安装、未启用、暂无注入等真实状态。
- 含义是是否纳入该插件本轮原本会注入正文的资料，不触发它重新生成记忆/大纲，不遍历其所有私有存储。
- 勾选状态只作用于规划 API，不能开关正文中的插件注入。
- 用明确来源键、位置、深度和角色标记接入，避免重复加入。后续通过适配器注册新插件。
- 预设显式引用某插件宏时，宏也是该资料的一条进入路径；未勾选时不能让它绕过控制，需在隔离的宏解析层处理，并提示宏依赖。不能以改动原插件全局状态实现。

### 楼内显示

一个“楼内显示规划”开关。开启时在最终 AI 回复楼层附加可折叠规划视图，默认折叠。

- 规划原文保存在该消息的插件 metadata 内，不追加到 mes 正文，不经正文正则重写，也不自动加入之后的聊天历史。
- 规划按聊天、消息和 swipe 版本绑定，重生成/翻页只显示对应版本；失败、取消、不存在规划的楼层不冒用前次结果。
- 刷新/重新打开聊天后可恢复；编辑原文导致旧规划失配时标明历史规划，不当作新生成结果。
- 展示仅用文本节点，不能执行模型返回的 HTML/脚本。楼内规划用独立 iframe 渲染，继续只同步五项主题变量；关闭显示不删除已保存数据。
- 该开关与“将规划注入正文 API 上下文”相互独立，关闭显示仍正常传递规划。

## 预设页

顶部：本地开关方案下拉、新建/覆盖/删除图标；其下为酒馆预设选择器。

- 从酒馆读取预设副本，按照 prompt_order 呈现和执行；不直接以 prompts 数组或条目自身 enabled 推断生效顺序。
- 方案保存所选预设身份、组/条目启用覆盖和必要的版本指纹。不再读取或复用预设编辑器的快照方案。
- 兼容柏宝箱 `extensions.baibaiToolkit.presetPromptGroups`，正确显示组名、组顺序、组内条目顺序、折叠与组开关。对无分组预设保留原顺序和未分组区。
- 视觉分组顺序与真实执行顺序分别明确处理，不因为渲染分组就擅自重排执行。支持组级勾选、条目级勾选及部分选中状态。
- 条目行点击打开正文详情，标题和开关互不冲突。详情默认只读；用户没有要求编辑预设正文，此版不增加原地编辑功能。
- 原预设变化时按稳定条目 ID 匹配已有覆盖，提示新增/删除项；不悄悄把旧开关套到同名新条目。
- 修改、保存、覆盖方案均不回写原生预设或柏宝箱分组缓存。

## 世界书页

顶部：本地世界书方案下拉和三个图标操作。主体分别列“全局世界书”“角色世界书”“插件开启的世界书”。

- 全局/角色绑定来自当前聊天环境；角色的主世界书及额外世界书均读取。聊天专属世界书如存在也应明确显示归属，不能默默漏掉。
- 额外世界书通过选择页添加，可搜索，避免同一本书重复注入。全局和角色重复挂载的同名书保留来源提示但生成时去重。
- 书级开关、条目级开关、条目正文详情；方案保存书名及稳定 uid 对应的启用覆盖，不更改原书的 disable 字段。
- 用户已明确选择：开启仅代表参与扫描，仍遵守原有关键词、常驻等激活规则，不直接发送全部启用条目。
- 扫描时还需核对次关键词、递归、选择逻辑、概率、深度/位置、预算、冷却/粘滞等原生语义；未支持的行为必须列明，不能以简单 includes 搜索冒充原生兼容。

## 上下文构建与隔离

1. 等待酒馆当前回合及兼容插件的前置处理就绪，冻结角色、历史、用户输入、插件注入和本地选择快照。
2. 在私有副本中按选择解析预设、宏和世界书，保留指令角色/位置，不直接调用会更新全局变量、计数或原生活动预设的有副作用路径。
3. 独立规划请求只包含所选来源，并提供调试用来源清单/字符统计用于测试验证，不在产品默认界面铺技术日志。
4. 校验返回规划标签后，仅将规划与正文阶段引导加入原正文请求；正文请求原先的预设和世界书不替换为规划配置。
5. 正文完成后绑定规划与实际消息/swipe；启用显示时渲染楼内面板。

核心实现风险：旧版最终 messages 已丢失部分来源标记。不能简单删字符串来排除记忆/世界书，也不能通过附加另一份预设实现“替换”。需要核对/抽取 1.18.0 的来源组装流程并建立私有上下文适配层。隔离宏副作用和世界书扫描状态是开发与验证重点。
